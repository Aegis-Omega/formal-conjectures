# AEGIS Math

The mathematics on this branch, kept as one library with one rule: every result carries
exactly one kind of evidence, and no kind is promoted to another.

| kind | meaning |
|---|---|
| `lean_kernel` | checked by the Lean kernel in CI from source; axioms only `propext`, `Classical.choice`, `Quot.sound` |
| `numerical` | reproducible computation; not a proof |
| `literature` | published or preprint result, not formalized here |
| `external_claim` | reported by another system, not replayed |
| `open` | not proved |

Each entry is self-contained (its statement, source blob and the run that checked it) and is
also a part of larger chains through `depends_on`.

## Files

* `AegisMathCoreV1.lean`: the Lean entry point. Aliases, under `AegisMath.*`, of kernel-checked
  theorems: the window-exhaustion frontier (`Windows`), the final-sign criterion (`Criterion`),
  the moment-killer range (`MomentKiller`) and two obstructions (`Obstructions`). It proves
  nothing new. It is compiled from source in `rh-cvs-window-l65-source.yml`, in the same DAG as
  the windows, and `audit.py` there requires all nine aliases with standard axioms.
* `CATALOG.json`: all entries, generated by `catalog.py` (run from the repo root). Lean
  statements are read from the sources; a moved or renamed theorem stops the script.

## Current frontier

`AegisMath.Windows.rh_iff_windows_above_eleven_sixteenths`: RH is equivalent to the arithmetic
sign on the log windows `L > 11/16`. Those windows are open. The numerical lab
(`research/rh/checkpoints/20261101_lambda_lab_s1`) shows the margin there falls like
`exp(−4π e^{2a})`, so any producer of the remaining budget must degrade at least that fast.

Not RH.
